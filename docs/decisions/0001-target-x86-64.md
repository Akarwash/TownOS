# 0001 - Target x86-64 rather than i686

## Status

Accepted.

## Context

MiniOS began as a 32-bit project: the codebase was 32-bit and the learning
chapters in `learnings/` were written for the 32-bit protected-mode model. At the
point the decision was made, nothing substantial had been built on top of the
32-bit assumptions yet, so the cost of switching targets was near zero. The choice
was whether to continue with i686 or move to x86-64 before real work accumulated.

## Decision

Target x86-64 (64-bit long mode).

## Consequences

- The author's existing x86-64 assembly experience transfers directly.
- The target matches real modern hardware rather than a legacy mode.
- Long mode cannot be entered without paging enabled, so paging is mandatory at
  boot rather than something that can be deferred. This forces the boot path to
  build page tables before it can enter 64-bit code (see
  [0002](0002-2mb-pages-and-8mb-identity-map.md) and
  [../reference/boot-sequence.md](../reference/boot-sequence.md)).
- Address translation uses 4-level page tables (PML4 down), a bigger structure
  than 32-bit paging.
- There are fewer beginner tutorials for 64-bit bring-up than for i686.
- `pusha`/`popa` do not exist in 64-bit, so the ISR entry stubs must save and
  restore each register by hand. This is part of why `kernel/isr_stubs.asm` is a
  deliberately hand-written stub.
- Several `learnings/` chapters are still conceptually 32-bit and need rewriting
  for long mode. This is tracked as pending, not done silently.
